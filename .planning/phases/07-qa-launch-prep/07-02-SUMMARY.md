# Phase 07 Plan 02: Widget Typed Error Differentiation Summary

Three distinct error messages wired to widget via `getErrorMessage()` helper that parses the JSON body from `/api/chat` error responses — rate limit, spend cap, and generic/network failures each surface readable, distinct copy.

## What Was Built

Added `getErrorMessage(error: Error | undefined): string` helper to `widget/WidgetChat.tsx`. The helper parses `error.message` as JSON (since `HttpChatTransport` throws `new Error(await response.text())` on non-OK responses), reads the `error` field, and returns one of three fixed copy strings. `error` was added to the `useChat` destructure and the error banner now renders `{getErrorMessage(error)}` instead of the hardcoded "Something went wrong." string. The widget was rebuilt to `public/widget.js` bundling Plan 01's dark CSS redesign alongside Plan 02's error logic.

## Decisions Made

- `getErrorMessage()` placed above the `WidgetChat` component declaration (module-level function, not inside the component) to avoid re-creation on each render
- `JSON.parse` wrapped in try/catch — malformed or non-JSON error strings (network timeouts, DNS failures) fall through to the static generic message
- Parsed value used only as string comparison (`=== 'rate_limit'`, `=== 'capacity'`) — never executed, never rendered as raw HTML (React text nodes are escaped automatically per ASVS V5)
- `public/widget.js` is gitignored as a regenerated artifact; build verification confirms the bundle contains both the Slate Blue token (#6878A0) and the error differentiation logic
